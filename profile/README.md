<p>"你们支持白名单吗"这句话，在售前对话里出现频率极高，但十个人问的往往不是同一件事。有人指的是把办公网 IP 加到代理的放行列表，有人问的是子账号能不能限定来源地址，还有人关心的是成员能不能只看到自己的线路。这篇把白名单按层拆开，从网络层一直拆到组织层，每层说清楚配什么、怎么配、容易错在哪，最后给一张可以直接抄进内部文档的分层对照表。</p>

<h2>一、"白名单"这个词覆盖了五层</h2>
<p>把这五层混在一起谈，就会出现"你说是就是、说不是就不是"的扯皮。分层之后对话会清楚很多：网络层管谁的网络能连进来，传输层管用什么协议和端口，账号层管凭什么证明身份，组织层管谁能改配置，审计层管改完留下什么记录。下面四节逐层展开，最后一节给组合配置。</p>
<h3>五层的边界</h3>
<p>网络层是源地址过滤，典型形态是"仅允许 203.0.113.0/24 访问代理端口"。传输层是协议与端口约束，比如只开 443、只支持 SOCKS5 over TLS。账号层是子账号与令牌，决定"哪个身份能调哪个接口"。组织层是成员角色，决定"这个人能不能改白名单本身"。审计层是日志留存，决定"出事之后能不能复盘"。任何一层缺失，整体强度都按最弱那层算。</p>
<h3>为什么先分层再谈功能</h3>
<p>因为不同层的实现成本差一个数量级。加一条 CIDR 是几分钟的事，做一套令牌分级可能要改代码。先分层，才能判断服务商说的"支持白名单"到底覆盖到第几层，也才知道自己还缺哪块。</p>

<h2>二、网络层：IP 白名单加什么、怎么加</h2>
<p>这一层是狭义的白名单，也是最常被问到的那层。核心逻辑只有一句：只有列表内的源地址能建立连接，其他一律拒绝。</p>
<h3>只有固定出口才值得配</h3>
<p>白名单的前提是你的源地址固定。办公室专线、云主机弹性 IP、固定家宽都满足；移动网络、动态家宽、咖啡厅 Wi-Fi 不满足，因为地址会变，今天加进去明天就失效。判断方法是在自己网络里访问 ipinfo.io 连查三次，看 IP 是否一致，以及 whois 里的 netname 是否落在运营商动态池。动态出口的替代方案是账号密码加令牌，别硬上白名单。</p>
<h3>CIDR 和掩码的常见坑</h3>
<p>填 <code>203.0.113.7/32</code> 是只放行单个地址，填 <code>203.0.113.0/24</code> 是放行整个 C 段 256 个地址，填成 <code>/16</code> 就放行了六万多个。有人图省事填 <code>0.0.0.0/0</code>，等于关掉这层防护，控制台一般会提示风险，看到提示就别点确认。另外注意 IPv6，如果你的网络双栈，只加 IPv4 白名单会出现"能连但偶发失败"，因为部分请求走了 v6。</p>

<h2>三、传输层：协议、端口与加密方式</h2>
<p>很多"配了白名单还是连不上"的案例，问题出在这一层：白名单放行的是 IP，但端口或协议根本不通。</p>
<h3>HTTP 与 SOCKS5 的差别</h3>
<p>HTTP 代理只处理 HTTP/HTTPS 流量，配置简单，浏览器和 curl 都原生支持，用 <code>-x http://用户:密码@地址:端口</code> 即可。SOCKS5 是传输层代理，能带 TCP 和 UDP，适合非 HTTP 协议和一些客户端软件，curl 用 <code>-x socks5h://地址:端口</code>，注意 <code>socks5h</code> 里的 h 表示域名解析也走代理，少了这个字母会出现 DNS 泄漏，解析结果和你以为的出口不一致。选哪个看客户端支持，不是越"底层"越好。</p>
<h3>端口白名单与出口一致性</h3>
<p>企业网络常只放行 443 出站。如果你的代理端口是 8080 或 1080，本地防火墙就会先把连接掐掉，现象是超时而不是拒绝，很容易误判成 IP 被封。排查用 <code>telnet 代理地址 端口</code> 或 <code>nc -vz 代理地址 端口</code>，先确认端口可达再谈业务。另外，端口开在哪个地区，出口就在哪个地区，同一台机器上多端口对应多地区时，配置里一定要标清，否则很容易"以为在用美国其实在法国"。</p>

<h2>四、账号层：子账号、令牌与最小权限</h2>
<p>白名单解决"从哪来"，账号解决"你是谁"。两者是乘法关系，不是替代关系。</p>
<h3>令牌分级怎么分</h3>
<p>常见做法是三级：只读令牌（查线路状态、查用量）、操作令牌（开通、释放、改配置）、管理令牌（改成员、改白名单、看账单）。自动化脚本只给操作级，监控只给只读级，管理级留在人手里并且开启二次验证。见过太多把管理令牌写进定时任务的例子，脚本一旦泄漏，等于把整个账户交出去。</p>
<h3>令牌轮换与使用留痕</h3>
<p>令牌建议 90 天轮换一次，轮换时新旧并存 24 小时，避免任务中断。每次调用在日志里记录令牌标识的后四位、调用时间、来源 IP、目标线路，不要记录完整令牌。日志落到独立存储，和业务日志分开，保留期按内部合规要求定，一般不少于 90 天。</p>

<h2>五、组织层：成员权限与审计</h2>
<p>最后一层最容易被忽略，因为小团队常常一个主账号大家共用。共用账号的问题不是安全洁癖，而是出问题查不到人。</p>
<h3>角色怎么划</h3>
<p>三个角色够用：管理员管成员与账单，运维管线路开通与配置，观察员只看状态和用量。超过十人的团队再加一个"审计"角色，只读日志、不能改任何东西。所有角色默认关闭导出权限，需要时单独申请。</p>

<h2>常见问答</h2>
<h3>家庭宽带能做 IP 白名单吗？</h3>
<p>答：可以，但要先确认地址是否固定。多数家宽是动态分配，重启光猫就可能换段。可以找运营商申请固定 IP，或者在路由器上做 DDNS 加脚本自动更新白名单，后者依赖服务商是否开放更新接口。</p>
<h3>白名单加了还是连不上，先查什么？</h3>
<p>答：按端口、协议、账号顺序查。先用 nc 测端口可达，再用 curl 单发看返回码，401 是账号问题、403 是权限或来源问题、超时多半是端口或防火墙。三步能定位八成情况。</p>
<h3>多个成员共用一个出口 IP 会互相影响吗？</h3>
<p>答：会。同一出口下并发共享带宽，一个人跑大批量任务会挤压其他人的连接。建议按项目分配不同出口，或者按成员做速率限制，别让所有人挤在一条线上。</p>
<h3>白名单能不能设置生效时间段？</h3>
<p>答：部分产品支持按时间段放行，比如只允许工作日的 9:00 到 19:00。这个功能对降低暴露面有帮助，但也容易造成夜间任务失败，启用前先确认自动化任务的时间窗。</p>

<h2>合规提示</h2>
<p>白名单是访问控制手段，用途应限于保护自有账号与自有系统，不得用于隐藏真实身份从事违反平台规则或法律法规的活动。所有配置变更建议走内部审批，保留变更记录。</p>
<p>代理服务的采购与使用需符合服务商条款及所在地法律。涉及个人信息、支付数据的业务，应评估数据出境与存储合规要求，不要把敏感数据放在不可控的中间节点上转发。</p>
<p>本文所述配置方法与参数取值来自通用实践，具体功能以服务商控制台实际提供的选项为准。</p>
